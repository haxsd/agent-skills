# 项目验证资产（project-verification）

验证的产物不是一个通过的测试，而是一份**下次还能直接跑**的资产。目标是任何人（或任何 agent）拿到这个项目，都能用一条命令回答“它到底跑起来没有、功能对不对”。

先生成一个最小可跑的版本，再按需加功能条目。空想的完整方案跑不起来，比没有更糟。

## 0. 先定“真实产物”

写下两个东西再动手：

- **入口**：CLI 命令、HTTP 端点、GUI 页面、库的调用方式，哪一个算“用户会用到的”。
- **可观察结果**：退出码、stdout、HTTP 状态与响应体、DOM 状态、截图、生成的文件。

写不出可观察结果，说明还没选定要验证什么。此时先问一句，不要生成一堆猜的命令。

## 1. 先探测宿主能力

不探测就生成，等于编造命令。逐项确认再往下：

| 能力 | 需要的证据 | 不具备时 |
|---|---|---|
| 后台启动长驻进程 | 能启动并读到就绪信号 | 改成一次性前台命令 + 超时 |
| 端口分配 | 能检测或绑定的端口 | 让被测程序用随机端口或临时目录 |
| 浏览器/截图 | 宿主有可用的浏览器自动化 | 退化为 HTTP 探测 + 文本/JSON 断言，并写明没有视觉证据 |
| 在目标项目新建目录 | 用户已授权 | 只生成到临时目录，交付时说明 |

拿不到证据就按更弱的能力生成，并在资产里注明缺了哪一段。不要写一条本机跑不通的命令。

## 2. 生成四段结构

放在目标项目的 `.verify/<app>/`，一个 app 一份：

```text
.verify/<app>/
  launch     起服务并等待就绪（就绪信号，不是 sleep 固定秒数）
  doctor     起不来时回答“为什么”：端口、依赖、环境变量键是否存在（不打印值）
  drive      走一遍主要用户路径，产出证据
  evidence/  证据落点；gitignore 掉大产物，保留最后一次基线
  features.md 功能清单：功能 | 怎么触发 | 什么算通过 | 证据路径
```

每段的硬要求：

- **launch**：就绪判断绑定在真实信号上（端口可连、健康端点 200、日志出现指定行）。轮询有上限，超时即失败并打印最后 20 行日志。
- **doctor**：只读，不施工。只报告键名是否存在、版本是否满足、端口是否被占用；不打印密钥值，不自动安装依赖。
- **drive**：断言绑到用户看得见的结果。一个功能一条断言，失败时输出期望值与实际值，不只输出“失败”。
- **features.md**：初始只登记真正跑通过的功能。没验证过的功能留空判据，比写上假判据好。

`features.md` 用表格，四列固定：

```markdown
| 功能 | 触发 | 通过判据 | 证据 |
|---|---|---|---|
| 登录 | `drive login` | 跳转到 /home 且标题含用户名 | evidence/login.png |
```

## 3. 生成后必须自己跑一次

没跑过不算交付。顺序是 launch → doctor（故意制造一个失败场景看它是否说人话）→ drive → 检查 evidence。

- 全部跑通：把实际命令与关键输出贴进交付说明。
- 跑不通：修到能跑；确实受宿主能力限制的段落，写明哪一段没验证、缺什么、下次怎么补。

**不要**把“文件已生成”当成完成。生成物本身不是证据。

## 4. 之后怎么用

- 改动前先跑一次基线，把输出存成 `evidence/baseline-*`；改动后跑同一组命令，对比“旧值 vs 新值”。
- 同一状态的有效输出可复用，不重复跑来“再说一遍”；代码变了才补跑受影响的功能。
- 功能增删时同步 `features.md`。过期条目比没有条目更糟：它会让人相信一个已经不存在的行为。
- 资产随代码提交，跟着项目走，不放进技能仓库。

## 常见失败模式

| 现象 | 实际原因 | 修正 |
|---|---|---|
| launch 用 `sleep 5` 等就绪 | 没有就绪信号 | 绑定端口/健康端点/日志行，轮询到上限 |
| 测试绿但功能是坏的 | 断言绑在实现细节上 | 断言绑到用户可见结果 |
| agent 说验证过了 | 只信了自报 | 看命令、退出码和输出原文 |
| 换台机器全挂 | 硬编码了本机路径、端口、绝对时间 | 用相对路径、随机端口，时间只做相对比较 |
| doctor 打印了 `.env` 内容 | 把诊断当成了信息倾倒 | 只报键名存在性，值一律脱敏 |
| 没有浏览器却说有截图 | 能力探测跳过了 | 第 1 步不许跳 |

## 与相邻技能的分工

- [webapp-testing](../webapp-testing/SKILL.md)：具体怎么用 Playwright 驱动页面。本技能决定**验证资产长什么样**，它提供**驱动手法**。
- [env-doctor](../env-doctor/SKILL.md)：环境起不来时的只读诊断流程。生成的 `doctor` 是它结论的固化版本，不是替代。
- [agent-evals](../agent-evals/SKILL.md)：评的是模型输出质量，不是程序能不能跑。两者证据不能互相顶替。
- [verification.md](../finishing-a-development-branch/references/verification.md)：证据契约。本资产产出的就是那份契约要求的类型。
