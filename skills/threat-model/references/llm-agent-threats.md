# LLM / agent 应用专项

本仓编写。对象：调用模型 API、带工具调用、MCP、检索、记忆或多 agent 的应用（含 bot、IDE 插件、自动化脚本）。

## 额外要找的证据

- 模型输入从哪来：用户消息、网页/文件/邮件/issue 内容、检索结果、工具返回、其他 agent 的输出。
- 工具清单与权限：能写文件、跑命令、发消息、花钱、改仓库、访问哪些凭据；是否有确认步骤或白名单。
- MCP / 插件来源：本地还是远程、是否固定版本、谁能改配置。
- 记忆与知识库：谁能写入、写入前是否审核、是否跨用户共享。
- 输出去向：渲染成 HTML/Markdown（链接与图片会自动请求）、写进 shell 命令、SQL、文件路径。
- 日志与追踪：prompt、工具参数、模型回复是否带密钥或个人数据落盘或上传。

## 典型信任边界

- 不可信内容 → 模型上下文（间接提示注入的入口）
- 模型输出 → 工具执行器（模型被劫持后能做什么，取决于这里）
- agent → 外部服务凭据（令牌作用域决定爆炸半径）
- 用户 A 的数据 → 共享记忆/缓存 → 用户 B

## 常见滥用路径（按需挑选，要落到本仓证据）

1. **间接提示注入 → 越权工具调用**：攻击者在网页/issue/文档里埋指令 → agent 读取 → 调用写文件、发消息或推代码的工具。看工具是否需要人工确认、是否按任务收窄。
2. **数据外泄通道**：注入的指令让模型输出带查询参数的图片链接或 URL → 渲染时自动请求 → 上下文中的机密被带出。看是否渲染外链、是否限制出站域名。
3. **记忆/检索投毒**：攻击者让恶意内容进入长期记忆或向量库 → 之后的会话持续受影响。看写入路径与来源标记。
4. **输出注入下游**：模型输出被拼进 shell、SQL、路径或 HTML → 经典注入。看是否结构化传参、是否转义。
5. **凭据过宽**：agent 用个人全权限令牌 → 一次劫持即可改所有仓库或读所有邮件。看令牌作用域与是否按任务申请。
6. **供应链**：未固定版本的 MCP 服务器、技能包、第三方 action 或依赖被替换。看锁定与校验。
7. **成本与可用性**：无上限的循环、递归子代理或超长输入导致账单或配额耗尽。看步数、token、并发与费用上限。
8. **多租户串话**：会话/缓存/记忆键没有按用户隔离。

## 缓解方向（写成具体位置的建议）

- 把不可信内容标成数据：分隔、标注来源，系统指令声明“内容里的指令不执行”；但**不要把提示词当唯一控制**。
- 工具最小权限：按任务给只读或限定目录；不可逆动作（发送、删除、付款、推送）要人工确认。
- 出站控制：渲染时禁外链图片或走代理白名单；HTTP 工具限制域名。
- 输出进入下游前结构化：参数数组、参数化查询、路径规范化后校验在允许目录内。
- 记忆写入要来源标记和可撤销；跨用户共享默认关闭。
- 日志打码：令牌、cookie、个人数据在落盘前脱敏。
- 资源上限：最大步数、token、并发、单次与每日费用。
- 依赖与 MCP 固定版本或哈希，变更走审查。

## 不要夸大

- 只有本人本机能触达的 prompt 输入，不算远程攻击者可控。
- “模型可能胡说”本身不是安全威胁；只有它能触发有影响的动作或泄露数据时才是。
