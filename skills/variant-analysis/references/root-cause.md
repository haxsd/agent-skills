# 提取可搜索的根因

基于 Trail of Bits Variant Analysis 改写；CC-BY-SA-4.0，见本技能 LICENSE.txt。

## 校准记录

在搜索前填写：

- 版本和授权根：本次分析的 checkout、差异范围及代码库。
- 种子：已知错误位置、实际片段与复现或修复依据。
- 错误约束：为什么错误，而不只是做了什么。
- 必要前提：输入、状态、类型或调用方式满足什么才会发生。
- 防护：什么能使相似实例安全；如何验证它有效。
- 已知限制：是否只有片段、是否已修复、是否缺运行时条件。

## 安全缺陷

按输入源 → 处理/包装链 → 危险操作 → 防护建立模型。
例如命令注入的根因是“不可信字符串进入 shell 解析且没有有效阻断”，不是“出现 subprocess”或“函数叫 run_job”。

扩展轴可以包括等价命令执行 API、自封装函数、调用者、间接输入来源和不同字符串构造方式。
`subprocess.run(['echo', value], shell=False)` 不满足此处的 shell 解析前提；这不等于证明它不存在其他参数或业务风险。

## 普通逻辑缺陷

先写不变量，例如“匿名身份不能读取无主对象”，再追踪身份、所有权、空值与授权判断。
`owner_id == user_id` 在双方都为 None 时可能意外放行；只搜索相同字段名会漏掉其他模型的同根因判断。

其他轴：零与空值、状态迁移、返回语义反转、整数边界、不同调用顺序、缓存与未缓存路径。
只把真正共享根因的候选归为同族，不把不同错误机制强行合并。

## 精确匹配的作用

先命中种子，证明查询与版本对应；零命中优先核实路径、转义、代码移动或修复状态。
用户提供的种子已经被当前版本修好时，可基于已授权旧差异建立错误形态，但明确不是当前版本仍有原漏洞。
完全没有种子证据时，暂停变体泛化并转向初始诊断或审查，不自行补造证据。
