# 候选分诊：先寻找使它安全的证据

基于 Trail of Bits triage 方法改写；CC-BY-SA-4.0，见本技能 LICENSE.txt。

## 对每个候选核对

- 条件：是否真的满足种子的错误前提？
- 输入或状态：来源是谁、是否可控、可能的类型/空值是什么？
- 防护：校验、转换、参数化接口、类型限制和调用约束是否确实有效？
- 可达性：是否从实际入口能到达；依赖什么权限或配置？
- 行为证据：完整静态调用链、项目测试、实际复现，分别标明。

先看必要上下文，不凭单行或函数名称判断。配置未知、调用方缺失时，不能默认满足所有条件。

## 四类结果

**已确认同根因**：错误逻辑与必要条件有证据。说明是静态确认还是实际复现；只有前者时不声称跑过程序。

**待确认**：说清缺什么，例如配置值、输入来源、校验实现或入口连通性。提出最低成本的下一步。

**排除**：说明哪条必要条件不成立或有效防护在哪里。保留安全反例，供改进搜索使用。

**当前未可达的潜在缺陷**：错误条件本身成立但没有现有可达调用，单列风险，不等于已可利用漏洞，也不要假装代码不值得关注。

严重程度评估影响；置信度评估证据强弱。二者分开，不因代码“不好看”提高等级。
测试/示例/未部署代码单列，不与真实部署路径混计。

## 特别容易误判的情况

- `repr=False` 不代表所有序列化路径都排除了凭据。
- 同名 sanitizer 不证明本调用位置被正确保护。
- `None == None` 可能使匿名身份误通过授权。
- 安全 API 的字符串/列表形式可能有不同语义。
- `shell=True` 加常量命令与不可信命令不是同一事实。
- 外部入口不可达不代表错误逻辑不存在；应准确描述两层结论。

只有在用户授权的隔离条件下才执行最小验证；默认不运行目标、不发送攻击请求、不输出真实密钥。
