# 排查交付结构

本仓依据 Trail of Bits Variant Analysis 改写；CC-BY-SA-4.0，见本技能 LICENSE.txt。

交付给用户的报告可以写在对话中。需要内部落盘时遵循目标项目的记录边界，不默认在公开仓库生成审计报告或提交记录。

## 1. 种子与范围

- 版本、原始缺陷、错误前提与校准查询。
- 已授权范围、排除项、预算和工具能力。
- 种子是否在当前版本命中；若来自旧差异则明确标记。

## 2. 搜索过程

每个泛化轴列查询与变化、增量命中及复核进度。记录失败查询和噪声来源，避免下一轮重复。
不能在没有执行工具的情况下填写“已搜索”“零命中”或编造计数。

## 3. 候选结果

每项包含：

- 位置与必要调用方。
- 已确认 / 待确认 / 排除 / 当前未可达潜在缺陷。
- 共享根因与证据；防护查证或排除理由。
- 严重程度、置信度、静态/运行证据类别。
- 下一步最小验证或回归建议。

涉及凭据时仅用假 canary，不把值、连接串或真实数据放进报告。

## 4. 覆盖缺口与停止依据

哪些目录、输入源、API 或包装器没有覆盖；哪些候选未读；哪些运行条件未知；为何本轮停止。
“未发现新增确认项”与“确认所有路径安全”严格分开。

## 5. 回归与修复建议

先提炼已确认实例与安全反例，再建议项目测试或查询规则。规则应同时命中真实错误、排除安全反例。
未经授权不修改目标代码、不增加 CI 阻断、不提交或推送目标项目。
