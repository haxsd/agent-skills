# 逐轴泛化与覆盖记录

基于 Trail of Bits 的 abstraction ladder 改写；CC-BY-SA-4.0，见本技能 LICENSE.txt。

## 搜索顺序

1. 精确错误片段：必须确认命中种子或已授权旧差异。
2. 名称维度：放宽变量或函数名，保留错误结构。
3. 结构维度：不同参数位置、分支、调用封装、字符串构造方式。
4. 语义维度：等价 API、不同输入源和保护机制。
5. 边界维度：空、零、匿名身份、类型范围、状态顺序。

每次只改变一个有解释力的条件。每步记录：查询、变化轴、增量命中、已看数量、确认/待确认/排除数量。
如果批次太大，先按模块或 API 分组，把未读部分明确保留；不得声称已逐项复核。

## 选择工具

- 宿主 Grep/符号检索足以完成表面搜索时直接用，不为任务安装 CLI。
- 需要真实数据流或跨函数分析时，可使用已经验证可用的 Semgrep/CodeQL；先确认语言、构建条件、查询语义和授权范围。
- 本机工具通过 toolkit-map 定位绝对路径；工具未找到时说明本次查询范围与缺口，不推断全机没有，也不自动安装。
- 不将项目源码发给远程扫描服务；用户单独授权时仍先核对数据边界。

## 噪声与停止

新增命中约一半以上是反例时，说明当前轴放宽过度：回退，记录为何误报，再换另一轴。
比例是缩放工作量的信号，不代表丢掉剩余未读候选，也不是所有任务通用的统计门槛。

达到预先约定的模块、候选数或时间预算时，交付当前结果与剩余范围。
“本轮没有新增确认项”只说明本轮方法的结果，不等于全仓已穷尽。

## 示例命令（按宿主能力调整）

先命中已知调用片段，再分别搜索以下命令执行族：

- subprocess.run / Popen / check_output / call 的 shell 条件。
- os.system / os.popen。
- asyncio.create_subprocess_shell。
- 项目包装器与其调用者。

命中不是漏洞证据。参数来自字面量、有效白名单、无 shell 的参数列表或无法追清的配置时，按 triage.md 分别处理。
本包不提供可直接设为 CI 阻断的通用查询；项目规则先用真实正反例验证。
