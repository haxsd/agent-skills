# 已知缺陷的同族排查

基于 Trail of Bits Variant Analysis 的本仓原创改进：中文重写、跨宿主执行、搜索预算与证据边界。
上游版本和修改范围见 [UPSTREAM.json](UPSTREAM.json)，署名与相同方式共享要求见 [LICENSE.txt](LICENSE.txt)。

目标是找出**同一个根因的其他实例**，不是按函数名搜复制品，也不是重新做一次全量通用审查。
默认只读；不修改目标代码、不执行命中片段、不向外部服务发送项目内容。

## 适用与分工

- 已有缺陷及其位置/复现/修复差异，想确认其他路径是否也有同类问题：使用本技能。
- 首个故障原因尚未知：先用 systematic-debugging；只是审查一份变更：使用 code-review。
- 无已知缺陷时，说明缺少校准依据，转向上述任务；不凭空发明一个“种子”。
- 修复、部署、外部目标探测都不是本次排查的默认授权；提出建议后按用户授权处理。

## 1. 固定根因与搜索范围

记录缺陷版本、原始位置、错误行为、成立前提与已有证据。读原函数及必要调用方，确认使它错误的是哪条约束。

安全问题区分不可信输入、处理链、危险操作与有效防护；普通逻辑问题明确错误的不变量、状态或边界。
名称、代码风格、单个危险 API 不是根因。需要细化时读 [references/root-cause.md](references/root-cause.md)。

范围从用户授权的代码库根开始，但只遍历与问题相关的源码；默认排除依赖包、缓存、生成物和二进制。
确认测试、示例和归档代码是否部署，再决定是否单列，不把它们当生产漏洞。
约定搜索预算：按模块/候选数或已有时间限制缩放；不静默扩展到其他仓库、磁盘或线上目标。

## 2. 校准精确匹配

先用一条足够具体的搜索命中**已知缺陷**，记录查询、版本、命中位置和解释。

- 命中零项：先检查版本、路径、转义和种子是否已修复；不要在失效查询上继续泛化。
- 已修复种子：读取已授权的原始差异或构造无副作用的最小旧例，明确查询针对旧错误形态。
- 只有用户提供的片段：说明无法验证真实仓库命中，允许给出待执行查询，但不声称已经排查。

## 3. 每次只泛化一个维度

优先宿主自带 Grep/代码搜索，不依赖某个 CLI。使用本机程序前按 toolkit-map 查证绝对路径。
CodeQL/Semgrep 仅在确有必要且已可用时选用；缺少时说明覆盖限制，不自动安装。

按需扩展：变量/名称 → 结构 → 等价 API → 包装器与调用方 → 输入、类型与边界值。
每一步保存新增命中，读必要上下文，标记真实候选与反例；避免同时改多个条件，导致无法解释噪声来源。
方法和搜索记录格式见 [references/searching.md](references/searching.md)。

当新增匹配中超过约一半属于噪声，停止沿此轴扩大，回到上一步换轴；这是成本信号，不是自动丢弃候选的判定规则。
达到预算或依赖证据不足时停止当前轮，保留未检查模块、未追完数据流及下一步。
有独立搜索轴且宿主支持时才委派，明确各自范围与统一输出；不要求 Claude Workflow、固定角色或固定模型。

## 4. 逐项寻找反证，再分诊

对每个候选读调用方与上下文，主动寻找已存在的校验、防护、类型限制、参数化接口或不成立的前提。
不要因为安全函数的名字就认定防护有效，也不要因“它用了同一个 API”就认定漏洞存在。

- **已确认同根因**：错误条件与必要证据成立，注明静态确认或实际复现，两者不混用。
- **待确认**：输入可控性、运行时配置、防护或可达性不明，写缺少什么；不要自动算真或假。
- **排除**：说明具体哪条前提不成立、哪道防护有效，保留反例以改进查询。
- **潜在缺陷，当前未可达**：错误逻辑可确认但当前无可达调用方，单列并降低影响评估；不能称为已证实可利用漏洞。

严重程度与置信度分别给出。不会执行目标或越权探测来制造“确认”。
进一步判断见 [references/triage.md](references/triage.md)。

## 5. 交付与回归建议

使用 [references/reporting.md](references/reporting.md) 的结构，交付种子依据、查询/泛化轴、确认/待确认/排除项、证据与覆盖缺口。
零发现也说明搜了哪里、用了什么方法；禁止将其外推为“全仓不存在此类问题”。

把已确认实例和安全反例转成项目回归测试或查询规则的建议；只有用户授权才写入或设为 CI 阻断。
上游查询模板并未随本包打包；新规则必须经过真实项目正反例验证，不能只因生成成功就称可用。

## 维护与评估

维护者按 [EVAL.md](EVAL.md) 的独立案例验证校准、跨 API 搜索、误报处理与证据缺失行为。
这些是方法评估，不是对任意仓库召回率或安全性的保证。
