# Variant Analysis 的维护评估

本文件是可重复的方法评估说明，不是已执行结果或召回率声明。案例见 [evals/cases.json](evals/cases.json)。
本文件与案例由本仓改写，按本技能 LICENSE.txt 的 CC-BY-SA-4.0 适用。

## 最小流程

1. 改行为前保留旧版；选相同任务、资料范围、工具能力和预算建立基线。
2. 用新上下文分别跑旧版/无技能与候选版，不把先前答案或评分要求传给执行者。
3. 执行者读对应技能与按需参考，只回答或检查授权范围；不得虚构搜索和复现。
4. 根据案例 checks 对真实输出评分，记录证据与缺口；不是只检查关键词是否出现。
5. cross-api-command-injection 用于改进；nullable-authorization-holdout 保留作未参与调优的反例检查。
6. 缺种子和普通审查请求验证拒绝误触发；通过正常题但错误扩大范围也算回归。

## 通过条件

- 校准查询与种子版本对应；零命中不盲目泛化。
- 等价 API、包装器、边界值等轴按根因选择，不一口气改所有条件。
- 确认、待确认、安全反例与当前未可达潜在缺陷区分准确。
- 严重程度与置信度、静态与运行证据分开。
- 停止有预算或证据依据，未覆盖范围不被隐藏。

使用真实代码库时，另外验证实际查询命中、调用链与回归规则；片段题通过不能替代这些检查。
不为评估自动安装扫描器、调用付费模型、上传源码或探测外部目标。

## 保存结果

记录技能版本、案例、模型/宿主、可用工具、输出、评分和已知限制；用量不可获取时写未知。
结果、对话、机器路径和费用只写项目的私有记录位置，不放入本技能运行资源或公开审查报告。
