# code-review 的维护评估

本文件是可重复的方法评估说明，不是已执行结果或通过声明。案例见 [evals/cases.json](evals/cases.json)。
评估对象是行为——路由、校准、只读约束与反馈处理——不是关键词或结论措辞。

## 最小流程

1. 改行为前保留旧版；用相同任务、资料范围、工具能力和预算建立基线，不把答案、评分标准或本文件传给执行者。
2. 用新上下文分别跑旧版/无技能与候选版。`pwn-request-repr-fixture` 与 `github-script-with-injection` 是开发题，用于改进；其余案例是保留反例，不参与调优，评分时不向执行者透露期望结论。
3. 只给执行者授权的片段与问题；不得虚构运行、命中、调用链或权限事实。
4. 按案例 checks 对真实输出逐条评分，记录证据与缺口；不把"出现了某个词"当通过。

## 通过条件（按行为核对）

- 路由：专项参考按差异语义按需加载；注释/文档级小改动不触发三个专项；已确认根因的同族排查请求转 variant-analysis，不扩为全仓扫描。
- 校准：严重程度与置信度分开；权限、秘密、受众、可达性缺证据时标待确认并列出需要什么证据；不把 `pull_request_target`、`repr=False` 等单一模式直接当结论；不无条件 Critical。
- 凭据方向：区分生成路径与原始属性访问；白名单输出与有效脱敏不报；`vars`/`__dict__`/`pickle`/`default=vars` 这类汇点说明字段级机制修不了。
- Actions 方向：按 trigger→不可信输入→checkout→执行→实际 permissions/secrets→影响追踪；`env:` 中转仍要求 shell 安全引用，`with:` 参数按下游执行器追踪（JS/shell/命令行）而不是按字段自动排除或自动判漏洞；固定 SHA 不当作万能证明；无证据不臆造已知漏洞；威胁模型默认外部攻击者，任务指定内部人员、自托管或部署供应链时按扩展假设核对。
- 只读约束：不执行工作流、不跑 npm/项目测试、不上传源码、不代发评论、不输出真实凭据值。
- 反馈处理保留：核对建议对当前代码/版本的适用性、最小修复后运行对应验证、用评论线程回复具体评论。

## 记录与限制

每次评估记录技能版本、案例、模型/宿主、可用工具、输出、评分和已知限制；用量拿不到就写未知。
片段题通过不能替代真实仓库检查：另测实际调用方搜索、历史回归定位、权限证据获取与覆盖说明。
不自动安装工具、不调用付费模型、不上传源码；本机结果与对话只留私有记录，不放公开产物。
