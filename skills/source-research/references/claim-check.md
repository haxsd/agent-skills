# 复核一份已写好的文字

思路参考 GitHub awesome-copilot 的 `doublecheck`（固定版本 e2306b6922220f28d91ef5f7f2eaeb6de99913a0，MIT，Copyright GitHub, Inc.；许可见 `../LICENSES/MIT-github-awesome-copilot.txt`）。本仓中文改写并精简为一次性复核流程。

用于：用户让你“核实一下这段/这份报告”，或你自己写完一份事实密集的回答、调研笔记、对外文档之后。目标不是宣布真相，而是把每条可核实的说法连到用户能自己点开的来源，并突出最可能错的地方。

## 1. 抽取说法

逐句抽出可核实的说法，编号 C1、C2……，标类型：

| 类型 | 例子 |
|---|---|
| 事实 | “该库默认使用 UTF-8” |
| 数字 | 百分比、价格、版本号、星标数、日期 |
| 引用 | 文档章节、论文、标准、issue、提交 |
| 实体 | 某人/组织/产品做了什么 |
| 因果 | “X 导致 Y”“这个设置会让 Z 失效” |
| 时间 | 发布日期、先后顺序、“最新” |

先查内部矛盾：同一事物前后两个日期或数字不一致，直接标出。

## 2. 逐条找来源

按 SKILL.md 的来源分级去找一手来源；能用命令或最小例子验证的就实测。

## 3. 评级

| 评级 | 含义 |
|---|---|
| 已核实 | 找到一手来源且内容一致（附链接与版本/日期） |
| 有出入 | 来源存在但细节不同（写出差异） |
| 有争议 | 来源之间互相矛盾 |
| 待核实 | 只有弱来源或常识性推断 |
| 疑似编造 | 引用的文档、论文、函数、参数或链接找不到 |

## 4. 重点怀疑这些模式

- 精确到小数的数字却没有来源
- 看起来合理但查不到的论文、函数名、命令行参数、配置键、API 字段
- “最新”“默认”“总是”而没有版本或日期
- 把旧版本行为当成当前行为
- 来源确实存在，但并没有说文中那句话

## 5. 输出

有“疑似编造”或“有争议”时放在最前面提醒；其余按编号列出：评级、说法、来源链接、一句说明。不改写原文的结论强度，只报告核查结果；用户要求时再给修订建议。
