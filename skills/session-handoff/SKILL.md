# 会话交接

交接文档给“没有任何上下文的接手者”读。它要能单独使用，但不重复别处已有的内容。

## 写之前先核实

交接里的现状必须是当下查到的，不是记忆里的：

- 代码：`git status --short`、当前分支、`git log --oneline -5`、未推送提交、工作树或 stash。
- 进行中的东西：后台进程、CI 运行、PR 状态、定时任务；写清编号或链接和最后一次看到的状态与时间（带时区）。
- 查不到的写“未核实”，不要写成已完成。

## 放在哪里

- 默认写到系统临时目录（`$TMPDIR` 或 `/tmp`；Windows 为 `%TEMP%`），文件名 `handoff-<主题>-<YYYYMMDD-HHMM>.md`，不放进仓库，告诉用户绝对路径。
- 用户或项目约定了交接位置（共享目录、记录仓库、issue）时用约定位置；公开仓库不放内部交接资料。

## 结构

```markdown
# 交接：<主题>（<日期 时间 时区>）

## 目标与完成标准
一两句：要达成什么，怎样算完。下一会话的重点（用户指定了就照写）。

## 已核实的现状
- 仓库/分支/提交、PR、CI、运行中的进程，每项附链接或命令输出要点。

## 已做的决定
- 决定 —— 理由（尤其是否决过的方案和原因，免得接手者重走）。

## 未完成与阻塞
- [ ] 下一步（按顺序，第一项要具体到可以马上执行）
- 阻塞：等谁、等什么。

## 用户强调过的规则与偏好
- 只列与这项工作相关、接手者不知道就会违反的。

## 参考
- 规格、计划、ADR、issue、提交、diff 的路径或链接（引用，不复制正文）。

## 建议加载的技能
- 技能名：为什么需要。
```

## 规则

- 引用而不复制：已经在规格、计划、提交或 issue 里的内容只给路径或链接。
- 脱敏：不写 API key、密码、token、cookie、个人联系方式；需要时写“凭据在 <保险库/环境变量名>”。
- 简短：能放一屏就不要放三屏；细节留给参考链接。
- 写完自检：只看这份文档，能否回答“现在是什么状态、下一步做什么、做完怎么验证”。
