# 沉淀重复偏好为规则

用户反复纠正同一模式、表达固定预期时，主动提议把约定写下来，之后不必再说。目标是把**重复出现的偏好**变成**一条可维护的规则**，而不是把一次反馈永久化。

## 何时提议

- 同一模式被纠正 **2 次以上**（例如"用相对导入"、"不要默认导出"）
- 用户对代码风格或约定表达明显不满
- 用户说"我总是要…"、"永远不要…"、"每次你都…"
- 你在同一项目里重复犯同一个错误

## 如何提议

自然提出，别像说教：

```
我注意到你已经纠正过 [模式] 两次了，要不要写成一条规则，我以后固定遵守？
```

## 落点（按当前宿主选择）

| 宿主 | 落点 |
|---|---|
| Cursor | `.cursor/rules/<name>.mdc`（frontmatter：description、globs） |
| Codex / Claude Code / 其他 | 项目的 `AGENTS.md`（或该宿主认的指令文件，如 `CLAUDE.md`） |

写规则时保持短小，一个关注点一条，例如：

```markdown
- 使用相对导入，不用 @ 别名
- 不为显而易见的代码加注释
```

## 规则

- 只在真实的重复模式后提议，第一次纠正不要提
- 一个关注点一条规则，文件保持短小
- **先查已有规则/指令文件**：已有相关条目就更新它，不新增重复条目
- 用户已经直接授权写规则时，直接写，不再重复询问
- 作用范围要如实：不要把单个项目的风格推广成全局规则
