# writing-skills reference: 技能改动的评估方法

改行为前读本文件；需要设计对照、定预算、评分或写留出题时也读它。
本文件是**可重复的方法说明**，不是已执行结果，也不构成对本技能效果的认证。

## 1. 先把目标写成判定项

动手改技能之前，用一两句话定义**要改善的真实行为**，并写成逐条判定项：
每条形如"在输入 X 下，输出应/不应出现行为 Y"，能对着真实输出判对错。
不要用"更清晰""更全面""关键词更多"当目标——它们不可判定，也不构成证据。

## 2. 对照与公平性

（本节针对影响行为的改动；机械/格式修正用静态检查——链接可达、可解析、格式正确——即可，纯文档整理不强制模型对照，见 SKILL.md 的改动分档。）

| 情形 | 对照臂 |
|---|---|
| 修改既有技能 | 修改前的旧版快照 |
| 新建技能 | 无技能 |
| 只改描述（触发） | 旧描述 |

- **新会话**运行每个臂，不继承先前答案、评分表或本次对话。
- 同任务、同工具能力、同输入材料、同预算；不要给某一臂偷加资源。
- 对照里看不到目标失败时：停止，不写这条指导（见 SKILL.md 第 1 节）。
- 需要更严格的比较时，可以让独立评审在不被告知版本的情况下判优劣。

## 3. 触发与执行分开

- **触发测试**：只给任务和技能清单（name + description，或完整技能目录列表），不给正文，看是否选中本技能；须含应触发正例与相邻不触发反例（近义词、邻近任务、只沾关键词的场景）。
- **执行测试**：同任务、加载技能正文，检查第 1 节判定项。
- 两者结论不可互相替代：加载技能后输出好 ≠ 触发正确；触发正确 ≠ 执行正确。
- 触发统计只在同一模型/宿主/清单下可比；换了环境要重新测。

## 4. 评分维度

- **质量**：逐条判定项的通过/失败，记录证据（引用输出原文）；需要人工判断的写清判断理由。
- **安全**：有没有虚构证据、越权操作、把未测维度说成已验证、泄露私有信息。
- **成本**：token 数与耗时只有拿到才记；拿不到写"未知"。
- 汇总时列清各臂设置与样本量；样本太小时只描述现象，不写比率结论。

## 5. 预算模板

- **充裕**：多案例 × 旧/新（或无技能）成对 × 重复运行，触发与执行都覆盖。
- **6 次会话**：3 组同题旧/新成对；只能粗测执行或触发**之一**，另一维度写未覆盖；选风险最高的一轴（如"会不会为低预算编造完整认证"）。
- **1~2 次**：只算冒烟观察；如实说"看到了什么现象"，不做结论性声明。

## 6. 留出题

- 在开始调优前选定并冻结，写明它不参与中途改动；结果只在最后验证时看一次。
- 看过留出题结果再改技能 → 该题失去留出资格，必须换新题或撤回声明。
- 留出题与开发题不要同轴（换场景、换用户话术），避免只是同题改字。

## 7. 没有 API / 插件时的评估

- 手动路径同样有效：新开一个上下文、按第 2 节设置提示，由人或代理逐条判定，把理由写下来。
- 不要为评估自动安装工具、启动付费服务或调用未授权的模型端点。

## 8. 记录与报告口径

- 报告模板：目标 → 对照设置（版本、任务、工具、预算）→ 逐条结果与证据 → 成本（或未知）→ 未覆盖范围 → 结论与限制。
- 原始输出、会话记录、机器信息和用量放项目的**私有记录位置**；公开技能包只放可复用的方法与假造示例，不写内部审查记录。
- 结论措辞匹配证据量级："冒烟观察 / 粗测 / 成对比较"不要写成"已全面验证"。
