# 字体选择与字形覆盖

随包字体主要提供拉丁字形和设计风格，不保证覆盖中文、日文、韩文、阿拉伯文或其他文字。选字体时按以下顺序处理。

## 1. 先确认语言和文案

把最终要上画面的文字完整列出，包括标题、日期、地点、主办方、标点、数字和特殊符号。设计阶段的示例文案不能代替最终文案。

## 2. 选择有许可的字体

- 优先使用随包字体；每个家族必须保留对应 OFL 文本。
- 使用系统或用户提供的 CJK 字体时，确认其许可允许当前项目使用和再分发成品。
- 不把来源不明、许可不明或只存在于某台机器绝对路径的字体写进可移植成品说明。
- 需要随成品分发字体文件时，把字体和许可放在一起。

## 3. 验证覆盖

```bash
python scripts/check_font_coverage.py \
  canvas-fonts/WorkSans-Regular.ttf \
  /path/to/cjk-font.ttc \
  --text "活动主题 2026 年 10 月 27 日" \
  --json
```

多个字体按 fallback 栈处理：每个非空白字符至少被一个字体覆盖才算通过。脚本支持 TrueType、OpenType 和 TrueType Collection，不执行字体代码，也不依赖第三方 Python 包。

## 4. 看实际渲染

覆盖表只能证明 cmap 中有字形，不能证明排版正确。导出后检查：

- 没有豆腐块、方框、缺字或意外回退
- 中英文混排的字重、基线和间距协调
- 标点没有跑到行首/行尾的错误位置
- 字体子集嵌入后仍能正常打开

## 5. 常见误区

| 误区 | 事实 |
|---|---|
| 字体文件很大，所以一定支持中文 | 字体体积主要来自字形数量和表结构；必须实际检查覆盖 |
| 渲染器没有报错，所以字形完整 | 缺字通常被静默替换，报错只能证明字体文件被加载 |
| 系统里有中文字体，就可以直接写进交付 | 可移植性和再分发仍受许可、路径和嵌入策略限制 |
| 只用一款字体就够 | 中文、拉丁、数字和标点可能需要明确的 fallback 栈 |
